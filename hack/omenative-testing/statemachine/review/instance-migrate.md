# migrate — arrows and exceptions

## ARROWS (every outgoing transition of the two states)

| id | from → to | on | guard (as written) | verdict | change / question |
|---|---|---|---|---|---|
| T-migrate-complete | Migrate/CreateSurge → Empty | pod.deleted[source] | the surge is promoted Ready on the source's running revision and the source's pods and resources are gone | KEEP | record written last is the right crash anchor; matches `Migrate` tail order (promote → finalize → ledger → record). |
| T-migrate-deadline | Migrate/CreateSurge → Failed | timer.migrationDeadline | the migration record passed its deadline and the source's live pods are not all runtime-ready | CHANGE | add a completion branch: when the surge passes `surgeTailGatesPassed` and only the source is unhealthy, finish the migration instead of failing the source *and* tearing down the serving surge (today both sides are lost). |
| T-migrate-deadline-restore | Migrate/CreateSurge → Ready | timer.migrationDeadline | the migration record passed its deadline and every live source pod is runtime-ready | KEEP | un-drain is unconditional and RunningRevision untouched — correct revert; only the `before`-window cell hides this branch (see exceptions). |
| T-migrate-teardown | Migrate/CreateSurge → Delete/Drain | spec.teardown | teardown deletes a mid-migration pair like everything else, so the migration exclusion does not apply | CHANGE | teardown closes no record and writes no terminal ledger row; the parent-owned ledger keeps a non-terminal `Started` row that `importableLedgerMigrations` re-imports as fresh `Accepted` work on the next IR (the `ownerRotated` variant). |
| T-migrate-force-delete | Migrate/CreateSurge → Migrate/CreateSurge | timer.forceDelete | force-delete policy configured and a source pod is past its deletion deadline plus overdue slack while its node is gone/unreachable; both clocks required | KEEP | self-loop is right; the 5s `MigrateRequeueInterval` poll supplies the wake (unlike Delete/Drain there is no exact-boundary requeue, but the poll is tighter than the boundary). |
| T-migrate-teardown-deadline | Migrate/CreateSurge → Empty | timer.teardownDeadline | owner Terminating, teardown deadline passed, finalizer still held | ASK | same ledger leak as T-migrate-teardown; trade-off is that the deadline exists to release a wedged owner fast — my lean: best-effort terminal ledger mirror that never blocks the finalizer release. |
| T-migratetarget-promote | Migrate/SurgeTarget → Ready | pod.deleted[source] | the surge passed its rotation and availability gates and the source's pods are drained and deleted | KEEP | pair-identity preconditions (`confirmMigrationCompletionPair`, `migrationPromotedSurgeMatches`) hold on both the fresh and the crash-resume path. |
| T-migratetarget-expired | Migrate/SurgeTarget → Delete/Drain | timer.migrationDeadline | the record passed its deadline, so the pin is dropped and the unpinned index leaves the plan | CHANGE | paired with T-migrate-deadline: unconditional teardown of a Ready, in-rotation surge is the wrong default when the source is the unhealthy side. Reusing the ordinary scale-down pipeline for the teardown itself is right. |
| T-migratetarget-teardown | Migrate/SurgeTarget → Delete/Drain | spec.teardown | teardown deletes a mid-migration pair like everything else | CHANGE | same unclosed record + non-terminal ledger row as T-migrate-teardown. |
| T-migratetarget-teardown-deadline | Migrate/SurgeTarget → Empty | timer.teardownDeadline | owner Terminating, teardown deadline passed, finalizer still held | ASK | same as T-migrate-teardown-deadline; lean best-effort mirror. |

Arrow-level gap (no transition to review, noted here): `Migrate/SurgeTarget` has no force-delete arrow — a wedged *surge* pod cannot be escalated until expiry unpins the index, while the mirror-image source pod can. Asymmetry is deliberate per the cells but is the reason a wedged surge always costs the whole deadline.

## EXCEPTIONS (cells that contradict their event's meaning, an arrow, or the rubric)

| cell (state · event[variant] · windows · transition) | current outcome | why it is an exception | recommended outcome | who decides |
|---|---|---|---|---|
| Migrate/CreateSurge · pod.stuckTerminating · all · — (review, #878) | escalate when forceDelete configured; **parks** when not | with no ForceDeletePolicy, `migrationTailReady` reports the wedged-but-drained source as tail-ready, expiry defers forever, and the drive's delete loop skips Terminating pods — the record never reaches a terminal phase, violating the liveness rubric outright | bound the park with a second deadline (fail the record, keep the surge), or make a Terminating pod on a gone node force-deletable independent of policy | owner call |
| Migrate/CreateSurge · pod.stuckTerminating · all · — (same cell, second effect) | parked record stays oldest non-terminal | `NextManualMigration` always re-picks the parked record, so every queued request behind it expires unattempted — the exact "wedged Terminating source starves queued records" failure | dispatcher skips a record parked past its deadline and drives the next one | code fix |
| Migrate/{CreateSurge,SurgeTarget} · spec.migrateRequest · all · — (review, #832) | defer — queued as `Accepted`, serial oldest-first | the note omits that the queued record's `Deadline` is already running (`accept + instanceReadyTimeout`); a second request can expire with blocker "surge never allocated" without ever being attempted, and the queue is unbounded by design | park the deadline while `Phase=Accepted && SurgeInstance==nil` — stamp/rebase it from `AllocatedAt`, which the record already carries for the capacity gate | code fix |
| Migrate/{CreateSurge,SurgeTarget} · spec.pauseTrue, spec.pauseFreeze · all · — | defer, "equally resumable" | a paused plan returns before both the expiry and the drive pass, but the record deadline keeps running on wall-clock; a pause longer than the remaining deadline makes unpause fire expiry first (it is planned before the drive) — the migration is *not* resumable, it is executed as a failure | park the deadline while paused, or say plainly in the cell that pause forfeits the migration | code fix |
| Migrate/{CreateSurge,SurgeTarget} · pod.schedulingGated · all · — | ignore; "gating parks the operation deadline but not the record Deadline" | same root cause as the two above: admission-gated time is charged to the migration, and the expiry blocker text ("surge pods never became ready") never names the queue, so the operator cannot tell a gated surge from a broken one | park the record deadline while every surge pod is gate-held, or at minimum name the gate in the blocker | owner call |
| Migrate/CreateSurge · timer.migrationDeadline · before · — (review, #878) | transition → Failed, guard "source pods not all runtime-ready" | the before-window key has no transition, so this single cell is the whole standing-start answer — yet the healthy-source answer is Ready (T-migrate-deadline-restore) and is reachable only through that transition's boundary/after cells; the grid therefore asserts an outcome that is wrong half the time | restate the outcome as branch-on-observation (Ready \| Failed) in the before cell, matching `restoreSourceFromObservation` | code fix (table) |
| Migrate/CreateSurge · timer.migrationDeadline · before/@T-migrate-deadline **and** Migrate/SurgeTarget · timer.migrationDeadline · before/@T-migratetarget-expired (review, #878) | source → Failed, surge → Delete/Drain, in the same pass | `expireMigrationRecord` has exactly one non-completion outcome; when the surge is runtime-ready, in rotation and Available while the source is *not*, expiry destroys the only healthy side and stamps the other Failed — the index ends with zero serving capacity | add the symmetric carve-out: surge tail gates pass + source unhealthy → drive the completion tail (delete the source pods, promote) rather than expire | owner call |
| Migrate/{CreateSurge,SurgeTarget} · timer.operationDeadline · all · — (review, #871/#878) | ignore — "stamped but never consumed" | truthfulness: the pin carries `Operation.Deadline = stampTime + instanceReadyTimeout`, a *different* clock from the record's `acceptTime + instanceReadyTimeout`, and it is re-stamped on every pre-SurgeReady re-ensure; the Instance status an operator reads shows a deadline that is both later than the real one and inert | stop stamping `Operation.Deadline` on a Migrate pin, or mirror the record's Deadline into it | code fix |
| Migrate/{CreateSurge,SurgeTarget} · spec.teardown · all · — | transition → Delete/Drain | the pair is deleted but the record is never closed and no terminal ledger row is mirrored; because the ledger is parent-owned it outlives the IR, and `importableLedgerMigrations` resurrects the UUID as a fresh `Accepted` migration with a new deadline — precisely the resurrection the expiry path calls a HARD step | close the record and mirror a terminal ledger row when teardown admits a Migrate-pinned index | code fix |
| Migrate/{CreateSurge,SurgeTarget} · spec.replicasUp · all · — | defer | an accepted migration returns from the dispatcher before the Create pass, so a scale-up (autoscaler capacity) is blocked for the whole migration — unbounded in the parked case — with no event; the Restart branch already has the precedent carve-out (`CreateFreshIndices` during restart) | mirror the restart carve-out: create fresh indices while a migration is mid-flight | code fix |
| Migrate/CreateSurge · gang.podGroup[Unschedulable, ScheduleTimeout, PhaseFailed] · all · — (**GAP**) | ignore | the event's normative meaning is "the PodGroup blocks or fails the gang"; nothing reads PodGroup status and the watch predicate drops status-only updates, so a gang the coscheduler gave up on is indistinguishable from one still waiting and burns the full deadline | read PodGroup status into the drive's blocker message; a `PhaseFailed`/`ScheduleTimeout` group should fail the record early | code fix |
| Migrate/SurgeTarget · gang.podGroup[Unschedulable, ScheduleTimeout, PhaseFailed] · all · — (**GAP**) | ignore | same blindness on the row that actually owns the surge PodGroup | same | code fix |
| Migrate/CreateSurge · spec.gangWidth · all · — (**GAP**) | ignore | the surge's desired set mirrors the *live* plan Runner list while the source keeps the pod set it already had, and extra surge pods are never deleted — the pair's widths diverge silently and nothing compares them; on promotion the surviving row carries pods from two widths | pin the surge width to the source's observed layout for the life of the record, or fail the record on a mid-flight width change | owner call |
| Migrate/SurgeTarget · spec.gangWidth · all · — (**GAP**) | ignore | target-side half of the same divergence | same | owner call |
| Migrate/CreateSurge · api.invalid · all · — (**GAP**) | defer | a 422 is wrapped as a blocked create and polled to the record Deadline exactly like a quota rejection; an unsatisfiable write burns the whole migration window and the operator sees "waiting to create surge pod" rather than a rejection | classify permanent rejections in `podCreateError` and fail the record immediately with the apiserver's reason | code fix |
| Migrate/SurgeTarget · api.invalid · all · — (**GAP**) | defer | same, on the create path that actually renders the surge pods | same | code fix |
| Migrate/CreateSurge · api.namespaceTerminating · all · — (**GAP**) | defer | a create that can never succeed is polled as if it were transient; least surprise says the record should fail with "namespace terminating", not time out | same classification fix | code fix |
| Migrate/SurgeTarget · api.namespaceTerminating · all · — (**GAP**) | defer | same | same | code fix |
| Migrate/{CreateSurge,SurgeTarget} · pod.unschedulable · all · — | ignore | not marked GAP but the same blindness as the PodGroup GAPs: nothing reads `PodScheduled=False`, so an overlay whose anti-affinity is unsatisfiable is indistinguishable from slow scheduling and always costs the full deadline, even though the pre-stamp overlay check exists precisely to fail that case early | surface `Unschedulable` into the record's Message so the blocker is truthful before the deadline | code fix |

## ROOT CAUSES

| root cause (file:function) | exceptions it explains | one-line fix shape |
|---|---|---|
| `pkg/controller/v1beta1/inferencereplica/migration_accept.go:consumeMigrationRequests` — `Deadline = acceptTime + instanceReadyTimeout`, pure wall-clock, never parked | spec.migrateRequest (queued starvation), spec.pauseTrue/pauseFreeze, pod.schedulingGated | stamp/rebase `Deadline` from `AllocatedAt` (execution start) and park it while queued, paused, or wholly gate-held. |
| `pkg/controller/v1beta1/workload/ops/migrate_expire.go:expireMigrationRecord` — one non-completion outcome: unpin+tear down the surge, restore-or-fail the source | T-migrate-deadline, T-migratetarget-expired, the before-window deadline cells | add a "surge tail gates pass + source unhealthy → drive the completion tail" branch beside the existing Draining carve-out. |
| `pkg/controller/v1beta1/workload/ops/migrate_expire.go:migrationTailReady` — the unconfigured-ForceDeletePolicy wedge exception defers with no bound, and `types/migration.go:NextManualMigration` keeps re-picking the parked record | pod.stuckTerminating (both effects) | bound the park with a second deadline and let the dispatcher skip a parked record so the queue drains. |
| `pkg/controller/v1beta1/workload/reconcile.go:ExtraInstanceIndices` (`includeMigrating=true` teardown path) — deletes a pinned pair without closing the record or mirroring a terminal ledger row | spec.teardown (both rows), T-migrate-teardown, T-migratetarget-teardown, both teardown-deadline arrows | close the record + `mirrorTerminalMigrationLedger` when teardown admits a Migrate-pinned index. |
| `pkg/controller/v1beta1/workload/reconcile.go` `case ActionMigrate` — returns `RequeueAfter` on `accepted`, so Update/Create never run, while `case ActionRestart` has an explicit `CreateFreshIndices` carve-out | spec.replicasUp (both rows) | mirror the restart carve-out for the migration branch. |
| `pkg/controller/v1beta1/workload/ops/migrate.go:migrationStatusMutation` — stamps `Operation.Deadline` from the stamp clock on a pin nothing consumes | timer.operationDeadline (both rows) | drop the field on a Migrate pin, or mirror the record's Deadline so the two clocks cannot disagree. |
| No reader for PodGroup status or `PodScheduled` anywhere in the workload layer (watch predicate drops status-only PodGroup updates) | gang.podGroup[Unschedulable/ScheduleTimeout/PhaseFailed] ×2, pod.unschedulable ×2 | read both into the record's Message, and fail the record on a terminal coscheduler verdict. |
| `pkg/controller/v1beta1/workload/ops/migrate.go` surge create path — `podCreateError` is not classified, every rejection is "blocked, poll to Deadline" | api.invalid ×2, api.namespaceTerminating ×2 | classify permanent apiserver rejections and fail the record with the reason instead of polling. |
| `pkg/controller/v1beta1/workload/ops/migrate.go:Migrate` — `surgeRunners` mirrors the live plan entry while the source keeps its existing pods, and the missing-pod diff never deletes extras | spec.gangWidth ×2 | pin the surge layout to the source's observed pod set for the record's lifetime. |
