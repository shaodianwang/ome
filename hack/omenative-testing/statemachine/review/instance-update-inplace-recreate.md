# update-inplace-recreate — arrows and exceptions

## ARROWS (every outgoing transition of the two states)

| id | from → to | on | guard (as written) | verdict | change / question |
|---|---|---|---|---|---|
| T-inplace-ready | Update/InPlace → Ready | pod.containersReady[source] | every changed container reports the target image at runtime, the marker is cleared, serving is back on, and any minReadySeconds window has elapsed | CHANGE | "serving is back on" is not checked: the pass *issues* MarkPodServing and promotes in the same pass; with minReadySeconds=0 no PodReady/IsServing re-read happens — add an unconditional `IsPodReady` loop before the promote, as recreate Phase C does |
| T-inplace-fallback | Update/InPlace → Update/Drain | spec.revision | the mode is re-resolved every pass and the new diff is no longer image-only under InPlaceIfPossible | CHANGE | the guard silently excludes InPlaceOnly, where the same event errors every pass forever (no arrow, no operation, no deadline) — add a `reject` arrow mirroring T-ready-inplaceonly-reject |
| T-inplace-retarget | Update/InPlace → Update/InPlace | spec.revision | new diff still image-only, so the stamp falls through its idempotency guard on the changed target | KEEP | — |
| T-inplace-strategy-surge | Update/InPlace → Update/Surge | spec.strategy | edited to SurgeThenDrain; the surge-owned guard protects only a surge-step row | CHANGE | the WriterUpdateInPlace drain hold is never released on re-resolve, so the surge starts with its source already out of rotation — release the hold (or restore serving) before dispatching another mode |
| T-inplace-strategy-recreate | Update/InPlace → Update/Drain | spec.strategy | edited to RecreatePod, so the mode re-resolves over the in-flight in-place step | KEEP | the patched pod is deleted, so the stale hold and marker die with it |

## EXCEPTIONS (cells that contradict their event's meaning, an arrow, or the rubric; includes every DECIDE and every # GAP cell)

| cell (state · event[variant] · windows · transition) | current outcome | why it is an exception | recommended outcome | who decides |
|---|---|---|---|---|
| InPlace · pod.deleted[source] · all · — | DECIDE (polls an empty pod set to the deadline) | the event means the pod is gone; no pass can repair it (Create skips an Updating row, the restart trigger declines below Ready, in-place creates nothing) while Drain's same cell repairs under the stable name — a lost single pod is waited out, not repaired | transition → Update/Drain: a missing pod re-resolves to recreate immediately | code fix (ops/update.go mode resolution) + owner confirming repair is not an InPlaceOnly violation |
| InPlace · pod.evicted · all · — | defer | an eviction is the same capacity loss as a delete and has the same non-existent repair path | follow the pod.deleted decision | code fix |
| InPlace · pod.terminating[source] / pod.stuckTerminating · all · — | defer | a pod carrying a deletionTimestamp can never converge to the target image; the roll patches a corpse until the deadline and the force-delete unwedger is unreachable from Update | re-resolve to recreate as soon as the pod is Terminating | code fix |
| InPlace · pod.phaseTerminal[Failed/Succeeded/Unknown] · all · — (GAP) | defer | a terminal pod can never report ContainersReady again, yet nothing reads phase and the roll polls it for the whole deadline | treat a terminal phase as a lost pod → recreate | code fix |
| InPlace · pod.ready[source] · all · — | defer ("never waits for PodReady") | the promote marks serving and stamps Ready in the same pass: nothing proves the gate went True, that no other writer still holds it, or that the pod is in the EndpointSlice — this is #1387 as fixed for Drain Phase C, and it releases the maxUnavailable slot before the pod is back in rotation | gate the promote on IsPodReady for every pod, unconditionally, before the minReadySeconds check | code fix (ops/update_inplace.go) |
| InPlace · timer.operationDeadline · all · — | escalate → Failed, "skipped entirely once the pod set is fully serving" | with markNotReady=false the pod never leaves rotation, so podSetFullyServing is true for the whole roll: an in-place update that never confirms its image is unbounded, with no deadline and no condition | do not retract the escalation for a row whose in-flight Operation targets a revision the pods have not confirmed | code fix (workload/escalation.go) |
| InPlace · spec.revision · all · T-inplace-fallback | transition → Update/Drain | true only under InPlaceIfPossible; single-pod InPlaceOnly returns a bare error from every pass — a repeated warning event, no operation, no RetryBlock, and no reachable deadline | reject: stamp Failed with a RetryBlock on the target and clear the operation (mirror T-ready-inplaceonly-reject) | code fix + owner call on mid-roll InPlaceOnly semantics |
| InPlace · spec.gangWidth[grow, runnerSetChanged] · all · — | transition → Update/Drain | InPlaceOnly promises rejection when the update cannot be done in place; chooseUpdateModeForInstance downgrades *every* multi-pod InPlaceOnly Instance to recreate — eligible or not — with no event and no condition | reject InPlaceOnly on a multi-pod Component at admission, or state the downgrade in the API doc; either way the cell must name it | owner call, then code/API |
| InPlace · spec.strategy · all · T-inplace-strategy-surge | transition → Update/Surge | the WriterUpdateInPlace hold survives the mode re-resolve, so the surge runs with its source already out of rotation — exactly the capacity dip SurgeThenDrain exists to prevent | release the in-place hold when the mode re-resolves away from in-place | code fix (ops/update.go) |
| InPlace · spec.pauseTrue / spec.pauseFreeze · all · — | defer, "the deadline is parked" | nothing parks it — deadline.go re-stamps only for admission-gated pods — so a pause longer than instanceReadyTimeout fails the Instance on the first post-unpause pass; and a pause taken after the drain leaves the pod out of rotation with escalation suspended | park the operation deadline on pause entry and re-stamp on unpause; state the out-of-rotation consequence in the note | code fix (workload/deadline.go) |
| InPlace · spec.policyTuning[gracePeriod] · all · — (GAP) | ignore | the API documents gracePeriodSeconds as the wait between mark-not-ready and the in-place mutation; no in-place path reads it, so a documented connection-drain knob is inert | honor it between the drain check and patchPodImages (requeue-based wait) | code fix; owner may instead narrow the API doc |
| InPlace · api.invalid · all · — (GAP) | defer | a 422 is permanent and every pass errors; because an erroring pass returns before escalateFromEvidence, "until the operation deadline disposes the attempt" never happens — the row stays Updating forever | classify an invalid write as terminal and dispose the attempt with a RetryBlock | code fix |
| InPlace + Drain · api.throttled[TooManyRequests, ServiceUnavailable] · all · — | defer, "the operation deadline still bounds it" | it does not: the erroring pass short-circuits escalation, so no deadline is consumed while the shedding lasts | correct the note and make the deadline reachable on the error path | code fix (root cause 1) |
| Drain · api.invalid · all · — (GAP) | defer | same as the in-place 422, plus the error aborts the whole update pass, so every later Instance in the Component stops rolling behind one permanently-invalid pod | classify + dispose; continue the per-Instance loop past one Instance's error | code fix |
| Drain · api.quotaDenied · all · — | defer, "the operation deadline keeps running" | the clock runs but is never read while the create keeps failing | same as the row above | code fix |
| Drain · gang.podGroup[OwnershipConflict] · all · — (GAP) | defer | a hard error before dispatch on every reconcile: no event, no condition, no deadline — an operator sees an Instance wedged Updating forever | surface a condition and let the deadline escalate even when a pre-dispatch pass errors | code fix |
| Drain · gang.podGroup[Unschedulable, ScheduleTimeout, PhaseFailed] · all · — (GAP) | defer | the controller writes a schedule timeout it never reads back, so a gang the scheduler has given up on is indistinguishable from a slow one | watch PodGroup status and map a failed/timed-out gang onto the stuck escalation | code fix |
| Drain · spec.gangWidth[shrink] · all · — (GAP) | ignore | a shrink landing after Phase B leaves bumped-incarnation pods outside the desired set: Phase C waits on them and nothing reaps them after the promote | Phase B deletes bumped-incarnation pods whose name is not in the desired set | code fix (ops/update_recreate.go) |
| Drain · spec.strategy · all · T-drain-strategy-inplace | transition → Update/Drain ("keeps this roll on recreate") | contradicts its own arrow (→ Update/InPlace), and the arrow's behavior is unsafe: in-place inherits a pod drained under a writer agent it never removes (Ready on a pod out of rotation) or no pod at all (no repair path) | hold the recreate in control once its Incarnation bump is committed; then the cell's text becomes true | code fix (ops/update.go) + owner on widening the surge-owned rule |
| Drain · spec.pauseTrue / spec.pauseFreeze · all · — | defer | a pause between Phase A and Phase B leaves the Instance with zero pods for the whole pause: Create is parked, the restart trigger declines below Ready, escalation is suspended, and the deadline is not parked either | pause between Instances, not mid-Instance: let the in-flight recreate finish Phase B before honoring the pause | owner call, then code |
| Drain · timer.forceDelete[overdueSlack, nodeUnreachable] · all · — (GAP) | ignore | Phase A issues the deletes but cannot unwedge them; the designed unwedger is reachable only from Delete and Migrate, so a pod pinned on a dead node holds the roll to the deadline and then fails a healthy Instance | run the force-delete escalation from the Update (and Restart) drain on the same clocks | code fix (force_delete.go wiring) |
| Drain · pod.waiting[*] / timer.operationDeadline / timer.stuckPodGrace · all · T-drain-stuck, T-drain-deadline, T-drain-stuckgrace | escalate → Failed with the operation preserved (multi-pod) | the next pass re-triggers it as a failedContinuation and the recreate stamp's guard requires Phase==Updating, so the Incarnation is bumped again and the gang is drained-and-recreated once per instanceReadyTimeout, forever, with no RetryBlock; the surge stamp guards exactly this storm | admit Phase==Failed at the same target in the recreate stamp's idempotency guard, and record a RetryBlock for multi-pod recreates | code fix (ops/update_status.go) |
| Drain · pod.phaseTerminal[Failed/Succeeded/Unknown] · all · — (GAP) | defer | Phase C polls a dead pod for the whole deadline although Phase B would recreate it under the same name for free | treat a terminal-phase bumped-incarnation pod as missing: delete it and let Phase B recreate | code fix |
| Drain · spec.revision · all · T-drain-retarget | transition → Update/Drain | each retarget re-bumps the Incarnation and restarts Phase A, so a target that moves faster than a roll takes leaves the Instance pod-less nearly all the time | ASK: adopt the new target only at the next incarnation boundary (bounded churn) vs today's immediate restart | owner call |

## ROOT CAUSES

| root cause (file:function) | exceptions it explains | one-line fix shape |
|---|---|---|
| workload/reconcile.go:Execute — any op-pipeline error returns before escalateFromEvidence, and executeUpdatePass returns on the first Instance error | InPlace api.invalid, Drain api.invalid, api.throttled (both), Drain api.quotaDenied, gang.podGroup[OwnershipConflict], the InPlaceOnly-ineligible retarget | run the escalation pass on the error path too, and continue the per-Instance loop past one Instance's failure |
| ops/update_inplace.go:inPlaceUpdate (promote block) — marks serving and stamps Ready in the same pass; only minReadySeconds>0 ever reaches a PodReady check | InPlace pod.ready, T-inplace-ready, the maxUnavailable slot leak, the stale-hold promote after T-drain-strategy-inplace | add the unconditional `IsPodReady` loop recreate Phase C already has |
| ops/update_inplace.go:inPlaceUpdate — no missing/dying-pod branch; the pod set is only ever polled | InPlace pod.deleted (DECIDE), pod.evicted, pod.terminating, pod.stuckTerminating, pod.phaseTerminal | when the expected pod is absent, Terminating or terminal, re-resolve the mode to recreate |
| ops/update.go:chooseUpdateModeForInstance — multi-pod InPlaceOnly silently becomes recreate; single-pod ineligible returns a bare error | InPlace spec.gangWidth[grow], T-inplace-fallback under InPlaceOnly | one honest disposition for InPlaceOnly: reject at admission for multi-pod, and a Failed+RetryBlock reject mid-roll |
| ops/update_status.go:patchInstanceStatusRecreatingForUpdate — idempotency guard requires Phase==Updating, unlike the surge stamp which admits Failed | T-drain-deadline, T-drain-stuck, T-drain-stuckgrace, Drain pod.waiting | admit Phase==Failed at the same target so a failed multi-pod recreate stops re-bumping the Incarnation |
| workload/escalation.go:escalateFromEvidence — podSetFullyServing retracts the deadline regardless of whether the pods run the target revision | InPlace timer.operationDeadline, T-inplace-deadline | keep the deadline armed while the Operation's target revision is unconfirmed on the pods |
| workload/deadline.go (no pause awareness) + the paused-plan gate in workload/reconcile.go | InPlace and Drain spec.pauseTrue / spec.pauseFreeze | park the operation deadline on pause and re-stamp it on unpause; do not pause mid-Instance between drain and recreate |
| ops/update.go:UpdateWithPods — only isSurgeOwnedStatus holds a mode in control, so a strategy edit hijacks a committed in-place patch or a committed Incarnation bump | T-drain-strategy-inplace, T-drain-strategy-surge, T-inplace-strategy-surge, Drain spec.strategy | widen the owned-step rule to any committed step, or release the previous mode's pod-level state on re-resolve |
| ops/update_recreate.go (Phase B) — creates missing names but never deletes bumped-incarnation pods outside the desired set | Drain spec.gangWidth[shrink] | reap not-desired bumped-incarnation pods in Phase B, mirroring Phase A |
| workload/podgroup + ops/force_delete.go — PodGroup status is never read and the force-delete escalation is reachable only from Delete/Migrate | Drain gang.podGroup[Unschedulable/ScheduleTimeout/PhaseFailed], Drain timer.forceDelete | read PodGroup status into the stuck evidence and wire force-delete into the Update/Restart drains |
