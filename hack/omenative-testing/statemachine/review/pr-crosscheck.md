## Vocabulary additions the PRs imply

`spec.resetInstances` and `spec.releaseHeldRevision` are declared; the other three remain proposals.

| proposed event | family | variants | meaning | states |
|---|---|---|---|---|
| `spec.resetInstances` | spec | `all`, `indexList` | an operator names Failed Instances for teardown-and-rebuild through the `ome.io/reset-instances` annotation on the InferenceReplica: their pods are deleted (expectations recorded before each delete) and the preserved repair Operation is cleared; Phase and LastFailure are untouched, so the row lands in the fresh-start shape the Create pass rebuilds. Hash-excluded, so it is not a `spec.annotationOnly`. Mailbox discipline: effects commit before the annotation is consumed, re-delivery is idempotent. (#1490) | `Failed` — the only state it acts in. Every other state skips with a named reason (`Phase=<x>`), as do `still serving` (any pod in rotation) and `owned by Update/Migrate/Delete` rows in `Failed` itself |
| `spec.releaseHeldRevision` | spec | — | the sibling mailbox that releases a `Held` RetryBlock. `../audits/instance-events.md:300` files it as "covered by `timer.retryAt`/`gate.allow`", but #1490 shows the two verbs share one discipline (hash exclusion, consume-after-effects) and one gap: the input is an operator write, not a timer. Naming it makes the pair symmetric and lets `cells-failed.yaml:394`'s prose reference become a cell | `Failed` (under `gate.deny[Held]`) |
