# restart — arrows and exceptions

| id | from → to | on | guard (as written) | verdict | change / question |
|---|---|---|---|---|---|
| T-restart-ready | Restart/Drain → Ready | pod.containersReady[source] | old-incarnation pods are gone on a live read, the bumped-incarnation set is complete, and every pod is ContainersReady | CHANGE | add `and every pod PodReady after the serving-gate flip` — `recreateUpdate` (the identical drain/delete/recreate skeleton) requires `podreadiness.IsPodReady` on every new pod before promoting because a pod is not in its Service until PodReady is true; `Restart` Phase C flips the gate and stamps Ready in the same pass, so the row claims Ready with zero endpoints, and the next pass's update budget counts it as available (`ops/restart.go:372-393` vs `ops/update_recreate.go:150-172`; the README names promote-before-PodReady as the canonical boundary bug). |

| T-restart-stuckgrace | Restart/Drain → Failed | timer.stuckPodGrace | the grace elapsed on a recreated pod that holds a terminal waiting reason, and the pod set is not fully serving | KEEP | same edge as T-restart-stuck reached from the clock side; both stamps are idempotent. |
| T-restart-scaledown | Restart/Drain → Delete/Drain | spec.replicasDown | a restart pins nothing in the plan, so the index falls out when replicas drop and the scale-down wave admits it | KEEP | dropping a restarting index during a shrink is strictly better than dropping a healthy one, and both paths drain then delete, so the overwrite loses nothing. |
| T-restart-teardown | Restart/Drain → Delete/Drain | spec.teardown | the owner carries a deletionTimestamp so every observed index is treated as a scale-down extra | KEEP | teardown outranks repair; the scale-down pipeline runs alone. |
| T-restart-teardown-deadline | Restart/Drain → Empty | timer.teardownDeadline | the owner is Terminating, the deadline has passed since its deletionTimestamp, and the teardown finalizer is still held | KEEP | leaving surviving pods to ownerRef GC is the shared teardown contract, not a restart-specific choice. |
| (none — declared by a cell, no arrow exists) | Restart/Drain → Create/CreatePods | spec.policyTuning[restartPolicy] | the policy no longer selects RecreateInstanceOnPodRestart | CHANGE | see the exception row: this edge is both unlisted in `transitions.yaml` and unsafe as executed; the fix is to let the in-flight Restart run to completion, which deletes the edge. |

| `Restart/Drain · pod.evicted · all` | DECIDE | an evicted pod is terminated but not deleted, so it holds its target name: Phase B sees the name present and creates nothing, Phase C never sees a runtime-ready set, and the repair burns the deadline and lands Failed-with-operation — i.e. one eviction of a fresh pod permanently retires the Instance, which is strictly worse than the Create sibling (disposable, retried) | `outcome: escalate` at the reap: Phase B deletes any bumped-incarnation pod that no longer occupies its name (terminal phase or Terminating) and returns, recreating it on the next pass | code fix (`ops/restart.go` Phase B), answered together with the identical `Create/CreatePods · pod.evicted` cell already raised in the create review |

## ROOT CAUSES
| root cause (file:function) | exceptions it explains | one-line fix shape |
|---|---|---|
| `ops/restart.go:Restart` Phase B — the diff is `desired \ existing` keyed on name presence alone, with no `existing \ desired` arm and no liveness test on the occupant | pod.evicted, pod.waiting[DeadlineExceeded], pod.phaseTerminal, spec.gangWidth[shrink], spec.gangWidth[runnerSetChanged] | one shared `podOccupiesName` predicate (not Terminating, not terminal phase) plus a reap arm that deletes non-occupying and out-of-set bumped-incarnation pods; mirror the predicate in `ops/create.go:missingPodTargets` so Create and the recreate agree |
| `ops/restart.go:Restart` Phase C — promotes on `query.AllPodsRuntimeReady` alone, where `ops/update_recreate.go:recreateUpdate` additionally requires `podreadiness.IsPodReady` on every pod and then `podsAvailable` | T-restart-ready, pod.ready[source], timer.minReady, spec.policyTuning[minReadySeconds] | lift the two extra gates out of `recreateUpdate` into a shared promote helper both paths call |
| `ops/force_delete.go` is wired only into the scale-down and migration drains; `ops/restart.go` Phase A returns unconditionally while `len(oldPods) > 0` | timer.forceDelete, pod.stuckTerminating, pod.nodeLost | call the same force-delete evaluation from Phase A — a stable-name recreate has no other way past a wedged Terminating pod |
| `workload/reconcile.go:Execute` returns before `escalateFromEvidence` whenever the action pipeline errors, and `ops/create.go:createMissingPods` classifies nothing but `AlreadyExists` | api.invalid (and the unbounded tail of api.throttled / api.namespaceTerminating) | classify permanent create rejections as terminal evidence, or run the escalation pass on the error path so the deadline stays reachable |
| `status_aggregate.go:disposableAttempt` excludes Restart, so both Failed stamps preserve the operation, and `ops/restart.go:instanceLostGangMember` refuses to re-arm on any preserved non-Create operation | T-restart-deadline, and the permanence behind every escalate row in this state | separate "what was in flight" from "may not retry" — keep the operation for display, gate re-arm on a RetryBlock-style backoff |
| `plan_decision.go:Plan` plans `ActionRestart` only under the current policy with no hold for an in-flight Restart operation, and the `WriterRestartDrain` key added by Phase A is removed by nothing except the pod's own deletion | spec.policyTuning[restartPolicy], spec.pauseFreeze | an `isRestartOwnedStatus` hold (mirroring the surge hold) so a durable Restart operation always reaches Phase C, and an unwind that removes the drain key on any abandon path |
| `gang/gang.go` + `workload/watches.go` — PodGroup status has no reader and the watch predicate admits only generation/metadata changes | gang.podGroup[Unschedulable,ScheduleTimeout,PhaseFailed] | fold PodGroup phase into `ObservedSnapshot` evidence and admit status-only PodGroup updates to the watch |
| `ops/restart.go:revisionHashForInstance` falls back to `""`, and Phase A's drain loop `continue`s on an empty `ome.io/revision-hash` | endpoint.rotationIn[source] | make the empty-hash case explicit (refuse like the orphan branch, or document it as provably unroutable) instead of silently skipping the drain |
