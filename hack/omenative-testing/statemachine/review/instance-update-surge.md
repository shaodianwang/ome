## ROOT CAUSES

| root cause (file:function) | exceptions it explains | one-line fix shape |
|---|---|---|
| `ops/update_surge.go:surgeUpdate` — the release gate is pod-conditions-only (`AllPodsRuntimeReady`/`IsPodReady` ignore deletionTimestamp; the target's rotation is never read) | pod.terminating[target] ×3, endpoint.rotationIn[target], endpoint.rotationOut[target] ×3, containersNotReady[target] ×2 | require live (non-deleting) pods plus `drain.IsPodInRotation(target)` before stamping SurgeDrain |
| `ops/update_surge.go:surgeUpdate` — `len(oldPods) > 0` stands in for "the source is in rotation", and the source's gate is never read before SurgeDrain | both DECIDE cells, T-surge-source-lost-promote | make the predicate "a source pod is alive **and** routed", and require the replacement PodReady on the source-lost path |
| `ops/update_status.go:patchInstanceStatusSurgingForUpdate` — the deadline is stamped once at Surge entry, absolute, never re-armed | settle-consumes-deadline, the 6 pause cells, deadline-vs-drain rows | re-arm on each step advance and park the clock while paused, as gated deadlines already park |
| `escalation.go:podSetFullyServing` — deleting pods are skipped, so a healthy replacement alone satisfies `desired` | stuckTerminating ×2, timer.forceDelete ×2, T-surgedrain-deadline/-stuck/-stuckgrace, T-settle-deadline | treat a source stuck past its grace period as disqualifying, and give the surge path the delete wave's force-delete |
| `ops/update_surge.go:surgeUpdate` entry — the single/gang branch reads `inst.TotalPods()` from the live plan, unpinned | spec.gangWidth ×3 | pin the shape on the operation at entry, or fold gang width into the revision hash |
| `ops/update_gang.go:gangSurgeUpdate` — the source is unrouted and deleted in one pass, with no drain check and no settle step | the gang-shape rows of every SurgeDrain cell | reuse the single-pod drain + settle sequence for the gang source |
| `ops/update_status.go:patchInstanceStatusSurgingForUpdate` — the Failed-sticky guard requires a surviving `Operation`, which `disposableAttempt` has cleared | the two "Failed sticky" justifications, same-target re-surge loop | key stickiness on Phase+TargetRevision, or always record a backoff block on disposal |
| `status_aggregate.go` + `inferencereplica/status.go:computeRolloutStalledCondition` — a wait becomes visible only after LastFailure exists; PodScheduled, PodGroup status and terminal pod phases have no reader | pod.unschedulable ×3, gang.podGroup status ×2, phaseTerminal[Succeeded,Unknown] ×3 | derive a waiting reason from the observed blockers and surface it on RolloutStalled before the deadline fires |
| `ops/update_surge.go:waitForSurgeDrainSettle` — grace read from `InPlaceUpdateStrategy.GracePeriodSeconds` with a hardcoded 30s fallback | spec.policyTuning[gracePeriod] ×3 | own field for SurgeThenDrain, default supplied by config, no literal in Go |
| `transitions.yaml` keying — arrows are keyed to the announcing event rather than the guarding one | 4 undeclared arrows (rollbackTarget, minReady, rotationOut[source], settle promote) | key each arrow on the event that makes its guard true, and declare the missing edges |
