Deploy a model

Create one InferenceService on the control plane. OME selects a runtime, places it onto workload clusters, and drives the rollout. You don't pick nodes — you declare intent.

1

Model

Pick a Ready model from the registry. Selecting a model seeds architecture, format, and capabilities for runtime matching.

arch: llama · format: safetensors · fp8 · 405B · TEXT_GENERATION — Ready in 3 clouds
2

Runtime

Let OME auto-select the best ServingRuntime via the fetch-match-score pipeline, or pin one explicitly.

score 0.96 — beats vllm-h100 (0.81) on fp8 + PD support
3

Deployment mode

How the runtime is laid out across nodes.

4

Placement

Let OME place by live capacity (reads each cluster's Kueue), or pin to a specific workload cluster.

5

Replicas & autoscaling

6

Rollout strategy

How future revisions roll out. Applies on every update after the first deploy.

ome.io/v1beta1
apiVersion: ome.io/v1beta1
kind: InferenceService
metadata:
  name: llama-3.1-405b-instruct
  namespace: inference-prod
spec:
  model:
    name: llama-3.1-405b-instruct
    kind: ClusterBaseModel
  # runtime auto-selected — omit to let OME pick
  placement:
    strategy: BestFit
    accelerator: H100
  engine:            # prefill
    minReplicas: 4
    maxReplicas: 16
  decoder:           # decode
    minReplicas: 4
    maxReplicas: 16
  rollout:
    groups:
    - canary:
        steps: [10, 25, 50, 100]
        analysis:
          p95LatencyMs: 600
          errorRate: "0.5%"
  annotations:
    ome.io/deploymentMode: PDDisaggregated
